Graph engineering, but you can see the graph

The hottest idea in AI agents right now is that workflows should be explicit graphs, not loops. Every tool in that conversation is a code library. Here's what the same five patterns look like when the graph is the interface.

By Rutul, founder of ForkScape · 8 min read

On July 17, Peter Steinberger — the developer behind OpenClaw — asked six words: "Are we still talking loops or did we shift to graphs yet?" Within a day it had millions of views, and within a week "graph engineering" had a name, a wave of explainers, and a canon.

The idea underneath is real, and it's older than the name: a single agent spinning in a loop (act → check → retry) stops scaling the moment work genuinely branches. What replaces it is an explicit graph — specialized nodes, edges that route work between them, state that flows along the edges. Instead of one heroic agent with a fifty-line prompt, you declare a small organization: who does what, who hands off to whom, what has to be true before the next stage fires.

The writeups that followed converged on five canonical patterns. If you've read any of them, you know the list:

  • Prompt chaining — each stage gets a clean context window containing only what it needs, not the whole conversation so far
  • Routing — a classifier picks one of several paths by looking at its own output
  • Parallelization — fan out to independent workers, then join with a declared policy (all? any? majority?)
  • Orchestrator-workers — a coordinator discovers the work list at runtime and spawns workers to match
  • Evaluator-optimizer — a generator and a checker in a bounded loop until the output passes

And here's the thing nobody in the conversation seems to notice: every framework being discussed is a code library. LangGraph, CrewAI, Microsoft Agent Framework, Google ADK, LlamaIndex Workflows, the OpenAI Agents SDK — all of them ask you to describe your graph in Python or TypeScript, and the graph itself exists only in your head and your debugger.

You're describing a picture to a compiler

This is a strange place for the industry to have landed. The whole pitch of graph engineering is that the structure should be explicit — drawable, reviewable, reason-about-able. The five patterns are all fundamentally spatial ideas: branches, joins, cycles, fan-outs. And the state of the art for expressing them is:

workflow = StateGraph(AgentState)
workflow.add_node("researcher", researcher_node)
workflow.add_node("writer", writer_node)
workflow.add_conditional_edges(
    "researcher",
    should_continue,
    {"continue": "writer", "retry": "researcher"},
)
workflow.set_entry_point("researcher")
app = workflow.compile()

That's a picture, described to a compiler, through a keyhole. When it runs, you get log lines. When it breaks, you get a stack trace and a mental exercise: reconstruct the graph in your head, replay the state through it, find the edge that fired wrong.

Code-first graphs are the right call when the graph ships inside a product — a support pipeline serving thousands of tickets, a backend service, something headless and versioned and load-tested. If that's what you're building, use LangGraph; it's good at exactly that, and a canvas would be the wrong tool.

But most of the people riding this wave aren't embedding graphs in products. They're doing their own work — research, code, analysis, content — and wondering why orchestrating three specialized agents requires a Python project, a virtualenv, and a debugging session. For humans doing work, the graph shouldn't be described. It should be seen.

The five patterns, on a canvas

ForkScape is a desktop app where AI conversations live as nodes on an infinite canvas, and branches are the point: ask the same node two questions, you get two child branches — two directions from one shared context, instead of one scrolling thread that forgets where you were. That's been the product since day one; it turns out we'd been building graph engineering since before the name existed. As of this month, all five canonical patterns are shipped, visual, and testable:

Prompt chaining → reference links. A node reads exactly the nodes you've linked into it — a whitelisted handoff, drawn as a dashed edge, not an ever-growing transcript. The pattern's "clean context window" is literally visible: you can see what each stage reads.
Routing → conditional automations. "When the classifier finishes, match its output — auth goes to the careful branch, typo goes to the fast one, anything else hits the fallback." Declared on the canvas, first match wins, misses logged loudly.
Parallelization → joins with a policy. Three strategy agents run in parallel; the coordinator arms itself only when all three have finished (or any, if that's the declared policy). The join is a rule on the canvas, not a hope that the user remembered to wait.
Orchestrator-workers → spawn on demand. An agent node can spawn sub-agent branches at runtime — the work list discovered while working, each worker visible as its own branch with its own context, results folding back to the parent.
Evaluator-optimizer → a real cycle, with a cap. A Fixer writes code; a Tester runs the actual suite and reports honestly; a loop-back edge feeds the failure output into the Fixer as feedback — until the tests pass or five attempts are spent. You watch the loop run. When it stalls, it says so.

And the part that no log file gives you: gates. Any edge can require human approval before the next stage fires. In our stock-analysis template, three strategy agents and a risk coordinator run themselves — but the node that could place a (paper) trade sits behind a click that a human has to make. Human-in-the-loop isn't a callback you register; it's a gate you can point at.

Receipts, not vibes

The economic claim behind branching — that a graph re-sends radically less context than one linear thread — is measured in the app, not asserted. The dashboard meters every real call and compares it to what a single continuous conversation would have re-sent, with the counterfactual capped so the number stays honest. On real multi-branch sessions it lands around 70%+ less context re-sent. Linear canvas? It says 0%. We'd rather show you a small true number than a large flattering one.
